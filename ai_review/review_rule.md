# Code Review 規則（Review Rules）

請根據以下規則審查 `mr_request.md` 的變更內容，並生成最終的 Code Review 報告。

⚠️ **特別要求：只列出目前程式碼仍存在的問題**  
1. 僅輸出「最新程式碼版本中仍存在」且「尚未修正或改善」的問題。  
2. 若某段程式碼已被優化、刪除或問題已解決，請**不要列出**在報告中。  
3. 若舊程式碼中出現的問題已不存在，請完全忽略，不需標註「已修正」。  
4. 報告應只聚焦在**現有程式碼仍需改進之處**。

---

## 1 命名規則 (Naming)
- 變數、函式、類別名稱應清楚表意
- 命名應符合專案慣例（如 camelCase、snake_case）
- 避免使用模糊或單字母命名（除非為常見慣例）

## 2 可讀性 (Readability)
- 程式碼應具備良好縮排與結構
- 建議加上註解（若邏輯不明顯）
- 避免過長函式（可考慮拆分）

## 3 功能邏輯正確性 (Functionality)
- 修改是否符合需求？
- 是否有潛在邏輯錯誤或邊界問題？
- 建議加入單元測試驗證重要邏輯

## 4 安全性與錯誤處理 (Error Handling)
- 是否處理可能的例外情況？
- 避免 try-except 捕捉過廣（除非必要）
- 若涉及用戶輸入，應進行驗證與清洗

## 5 效能考量 (Performance)
- 是否存在明顯的效能瓶頸？
- 是否重複查詢或資料處理？
- 可否優化迴圈或資料結構？

## 6 文件與註解 (Documentation)
- 是否有足夠的 docstring 或區塊註解？
- 重要函式是否說明用途與參數？

## 7 語法錯誤 (Syntax Error)
- 是否有明顯的語法錯誤？
- 是否有編譯錯誤或執行時會立即失敗的程式碼？
- 是否有型別不匹配、缺少必要參數等致命錯誤？
- 是否有使用未定義的變數或方法？
